# Flappy Bird AI --- Deep Q-Network (DQN)

An AI agent that learns to play **Flappy Bird** using **Deep
Reinforcement Learning (DRL)** and a **Deep Q-Network (DQN)**
implemented with PyTorch.

The agent interacts with the Flappy Bird Gymnasium environment, learns
from its actions and rewards, and stores its best-performing model so it
can be loaded later in testing mode.

## Features

-   Deep Q-Network (DQN) implemented using PyTorch.
-   Epsilon-greedy action selection for exploration and exploitation.
-   Experience replay to learn from previously collected transitions.
-   Separate policy and target networks for more stable learning.
-   Bellman equation for calculating target Q-values.
-   Configurable hyperparameters through `parameters.yaml`.
-   Separate training and testing modes.
-   Saves the best-performing policy network to the `runs/` directory.

## How It Works

The agent learns by repeatedly interacting with the environment.

1.  **Observe:** The environment provides the current state.
2.  **Choose an action:** The agent either explores by choosing a random
    action or exploits by selecting the action with the highest
    predicted Q-value.
3.  **Receive feedback:** The environment returns the next state,
    reward, and episode-ending information.
4.  **Store experience:** During training, the transition is stored in
    replay memory.
5.  **Learn:** The policy network is updated using a mini-batch sampled
    from replay memory.
6.  **Update target network:** The target network periodically receives
    the policy network's weights.
7.  **Save:** The best-performing policy model is saved for later
    testing.

### DQN Architecture

The project uses a feed-forward neural network to estimate the Q-value
of each available action from the current state.

The network is defined in `dqn.py`. In the version supplied with this
project, it uses:

``` text
Input state
    |
Linear layer (256 neurons)
    |
ReLU
    |
Linear layer (number of actions)
    |
Q-values for available actions
```

The agent chooses the action with the highest Q-value when it is
exploiting the learned policy.

### Experience Replay

The replay buffer stores transitions:

``` text
(state, action, next_state, reward, terminated)
```

Instead of learning only from the latest transition, the agent samples a
random mini-batch from stored experiences. This helps reduce
correlations between consecutive experiences.

### Exploration and Exploitation

During training, epsilon-greedy selection controls the balance:

-   **Exploration:** Choose a random action with probability epsilon.
-   **Exploitation:** Choose the action with the highest predicted
    Q-value.

Epsilon decreases over training until it reaches the configured minimum.
During testing, the agent uses the learned policy without random
exploration.

## Usage

The command-line interface takes the hyperparameter configuration name
from `parameters.yaml`.

### 1. Train the agent

``` bash
python agent.py flappybirdv0 --train
```

This starts training using the `flappybirdv0` configuration. The best
policy network is saved to:

``` text
runs/flappybirdv0.pt
```

Training can be stopped manually with `Ctrl+C`. For a controlled
training run, specify an episode count:

``` bash
python agent.py flappybirdv0 --train --episodes 500
```

### 2. Test the trained agent

``` bash
python agent.py flappybirdv0
```

The testing mode loads the saved model and renders the game. In the
corrected `agent.py` version, testing runs five episodes by default and
does not perform training updates or save model weights.

To test for a different number of episodes:

``` bash
python agent.py flappybirdv0 --episodes 20
```

> Train the model before testing. If `runs/flappybirdv0.pt` does not
> exist, testing will report that the trained model is missing.

## Hyperparameters

The values are configured in `parameters.yaml`. The `flappybirdv0`
configuration includes:

  -----------------------------------------------------------------------
  Parameter                           Purpose
  ----------------------------------- -----------------------------------
  `epsilon_init`                      Initial probability of random
                                      exploration

  `epsilon_min`                       Minimum exploration probability

  `epsilon_decay`                     Rate at which epsilon decreases

  `replay_memory_size`                Maximum number of experiences
                                      stored

  `mini_batch_size`                   Number of experiences sampled for
                                      an update

  `network_sync_rate`                 Number of environment steps between
                                      target-network updates

  `gamma`                             Discount factor for future rewards

  `alpha`                             Learning rate used by the Adam
                                      optimizer

  `reward_threshold`                  Episode reward limit used by the
                                      agent
  -----------------------------------------------------------------------

Change these values in `parameters.yaml` to experiment with different
training configurations.

## Model and Training Output

-   `runs/flappybirdv0.pt`: saved policy network weights.
-   `runs/flappybirdv0.log`: records when a new best episode reward is
    achieved.

The model file contains the policy network's state dictionary. Testing
creates the same network architecture and loads those saved weights.

## Algorithm

The agent uses the Q-learning target:

\[ y = r + `\gamma `{=tex}(1-d)`\max`{=tex}*{a'}
Q*{`\text{target}`{=tex}}(s',a') \]

where:

-   \(r\) is the reward received.
-   (`\gamma`{=tex}) is the discount factor.
-   \(d\) indicates whether the transition ends the episode.
-   (s') is the next state.
-   (Q\_{`\text{target}`{=tex}}) is the target network's estimate.

The policy network is trained to reduce the difference between its
predicted Q-value for the selected action and this target, using mean
squared error loss.

## Notes

-   The saved model is created by training; it is not included
    automatically in a fresh clone unless you add it to the repository.
-   Training results depend on the hyperparameters, number of episodes,
    and environment behavior.
-   A model loading successfully does not guarantee that it has learned
    a strong policy. Evaluate its rewards across multiple testing
    episodes.
-   Keep the `dqn.py` network architecture consistent with the
    architecture used to create the saved model.
